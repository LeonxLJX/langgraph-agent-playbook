# 案例 11 · 结构化输出校验重试（🟡 中级）

> 一句话：**业务要的不是“一段话”而是强类型数据 —— 用 pydantic 校验，错了带反馈重试。**

## 难点是什么
很多下游（数据库、API、UI）要的是**带类型的结构化数据**（JSON/对象），不是自由文本。
模型经常输出少字段、类型错、甚至是纯文本 —— 直接传下去必然崩。

## 为什么会发生
让模型“自由发挥”是它的强项，但结构化输出需要约束 + 校验。不能只靠“提示它输出 JSON”，
必须有一道本地校验 + 纠错兜底。

## 生产级解法（看代码 `main.py`）
1. 定义强类型 schema（pydantic `BaseModel`），作为输出唯一真相。
2. 用 `model_validate_json` 校验；失败时**把校验错误作为反馈消息**塞回对话，
   让模型带着错误重试 —— 比“再来一次”收敛更快。
3. 设置上限 `max_struct_retries` 防无限自纠；超限优雅返回 None 并记录 attempts。
4. 生产可用 `model.with_structured_output(schema)` 让模型原生出结构，但仍要本地校验兜底。

## 调试清单
- [ ] schema 够严吗？必填字段、类型、约束都要写。
- [ ] 校验失败有没有把“具体错误”反馈给模型？没有反馈的重试是瞎猜。
- [ ] 重试上限设了吗？不设会无限自纠。
- [ ] 超限后有没有优雅降级（None + 可读提示）？

## 跑一跑
