# 案例 06 · 节点异常自愈与状态一致性（🟡 中级）

> 一句话：**某个节点崩了不能毁掉整次运行 —— 重试一次、记录错误、优雅降级，且状态一致。**

## 难点是什么
图里任何一个节点（尤其模型调用）抛异常，整个运行就失败。更隐蔽的是：
之前的副作用（工具已执行、消息已写）可能已经落盘，**状态半新不旧，不一致**。

## 为什么会发生
把裸 `model.invoke()` 直接当节点，异常会向上抛穿整个图；而已经写入的状态不会自动回滚。
生产里必须把“可能失败”当成常态。

## 生产级解法（看代码 `main.py`）
1. **错误边界**：agent 节点包一层 try/except，失败先重试一次（瞬时抖动可自愈）。
2. **失败不产残缺消息**：重试仍失败时，不把半截消息写进 state，而是标记 `failed`。
3. **优雅降级**：路由到 `fallback` 节点，用固定文案回应，而不是把堆栈抛给用户。
4. **错误可追溯**：`errors` 走列表 reducer，跨节点累计，能回看每次失败的记录。

## 调试清单
- [ ] 每个节点都包了错误边界吗？至少模型调用这种高频风险点要包。
- [ ] 失败时有没有写“残缺状态”？宁可少写，不要半写。
- [ ] 有没有降级路径？没有，一次故障就是一次用户可见的崩溃。
- [ ] 错误记录能不能查到（日志/state）？排查要靠它。
