# 案例 04 · 幻觉工具名拦截（🟡 中级）

> 一句话：**模型调了个根本不存在的工具，你要在派发前拦下，并且别让它反复瞎试。**

## 难点是什么
模型“幻觉”出一个工具名（或拼错、记错），直接执行必然报错。更糟的是它可能反复尝试
同一个非法工具，白烧 token 还不出结果。

## 为什么会发生
`bind_tools` 只是软约束，工具集一旦变大，模型更容易记混名字。生产里必须假设
“模型迟早会调错工具”，并把这件事变成可控的。

## 生产级解法（看代码 `main.py`）
1. **白名单校验**：执行前先查工具名是否在注册表里，非法调用不进执行器。
2. **有界自纠**：非法调用回传 `[工具不存在]` + 可用工具列表，让模型改正；
   同时统计非法次数，达到 `max_invalid_tool_calls` 后注入强制收尾，防无限自纠。
3. **守卫执行**：合法工具执行失败也用 try/except 兜底回传（与案例 01 同款）。

## 调试清单
- [ ] 工具名校验放在**执行前**还是执行中？要在派发前，别等执行报错。
- [ ] 错误消息有没有告诉模型“可用集合”？（没有它只能继续猜）
- [ ] 非法次数上限设了没？不设会无限自纠空转。
- [ ] 工具集大时，可以考虑在系统提示里给工具清单，进一步降低幻觉率。

## 跑一跑

python cases/04_hallucinated_tool/main.py --message "帮我发邮件给老板"  # 故意触发
pytest cases/04_hallucinated_tool -q
