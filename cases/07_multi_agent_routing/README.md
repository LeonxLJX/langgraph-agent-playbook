# 案例 07 · 多智能体路由与上下文隔离（🟡 中级）

> 一句话：**一个 Supervisor 决定把活派给谁，每个专业 Agent 只看自己的上下文，互不污染。**

## 难点是什么
一个需求常要多种能力（查资料 / 写文案）。把多种能力硬塞进一个 Agent：
- 上下文互相污染（查资料的系统提示影响写文案的判断）；
- 角色混乱，模型不知道此刻该干嘛。

## 为什么会发生
很多人把“会调工具”当成“能力多”，结果模型同时具备冲突的指令，行为不稳定。
生产上应该**拆成多个专业 Agent，再加一个调度者**。

## 生产级解法（看代码 `main.py`）
1. **Supervisor 节点**：模型把用户意图分类成角色（research / writer），写入 `state.active_agent`。
2. **条件路由**：按角色把执行权交给对应专业节点。
3. **上下文隔离**：每个专业节点用**自己的模型 + 自己的系统提示**，只接收用户原始诉求，
   不把调度者的中间结果带进去。
4. 专业节点的产出作为最终答复。

## 调试清单
- [ ] 每个专业 Agent 是独立的模型实例吗？共用模型最容易串上下文。
- [ ] 专业节点接收的是“用户原始诉求”还是“全部历史”？要隔离。
- [ ] 路由结果有没有写入 state？靠它做条件路由。
- [ ] 未知意图怎么兜底？（本案例回退 direct）
